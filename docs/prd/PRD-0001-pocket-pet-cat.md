# PRD-0001: pocket-pet 桌面猫 v1（状态 → 目标 的本地小模型）

- **状态**：draft → 待 DoD 硬度自检 + Doc QA 自检
- **关联愿景**：`docs/prd/VISION.md`
- **一句话**：给一块离线板子一只"会自己挑事做"的猫：状态行 + 8 个目标 + 14M 蒸馏学生 + 反射层。

## 1. 背景与动机

pocket-tank 已经证明：**14M 参数的学生、7.56 MB 的 Q4 权重、直接从 flash mmap、P4 上 10.6 tok/s**
可以在不联网的前提下驱动一个活的世界。它成功的结构是：

1. **反射层**（每帧 25 fps）负责所有连续动作（游动/避障/进食/擦缸），**不依赖模型**；
2. **顾问层**（每 2–5 秒一次）只回答一个问题：**"接下来想干嘛？"**——从 N 个目标里挑一个；
3. 状态以**一行文本**喂给模型（`zone 2 hunger 6 ... time day`），输出是一个**目标 token**。

这套结构对物种没有依赖。本 PRD 把它搬到**猫**身上：换状态、换目标、换世界，
推理引擎与内核**原样复用**。

## 2. 需求（每条都可二元判定）

### REQ-0001-001 状态行 schema（v1 冻结）

- **范围**：定义猫的状态行：字段名、取值域、序列化格式（`key value` 空格分隔、单行、≤ 48 token）。
- **必须包含**：`hunger energy bored clingy litter curiosity bold lazy` 八个数值字段（0–9 整数），
  `food toy owner litter_box window` 四个"方位"字段（`none`/`near <时钟位>`/`mid …`/`far …`），
  `stage`（`kitten`/`adult`/`elder`）、`last`（上一个目标）、`time`（`dawn/day/dusk/night`）。
- **非目标**：不做数值标定（那是训练后的事）；不做多只猫。
- **验收口径**：仓内三处对同一 schema 的表述**逐字段一致**——`docs/pet/state_line.md`、
  `include/pet_state.h`、`pocket_pet/state.py`；由 `uv run python -m pocket_pet.check_schema`
  比对并输出 `SCHEMA_OK fields=N`。
- **反作弊**：校验脚本必须**从 C 头文件解析**字段表（不是手抄常量），否则判 fail。

### REQ-0001-002 目标集（8 个）

- **范围**：`seek_food / sleep / play / groom / follow_owner / scratch / explore / hide`。
- **非目标**：不加第 9 个目标（词表要留余量）；不做层次化目标。
- **验收口径**：每个目标在 `docs/pet/goals.md` 有 ≤2 行定义 + ≥3 条正例；
  8 个目标名与 `include/pet_state.h` 的枚举**逐字一致**（同上脚本校验）。
- **反作弊**：正例必须来自种子标注（REQ-004）里真实出现的行，不能是编的。

### REQ-0001-003 情境采样器（多样且可复现）

- **范围**：在状态空间里按分布生成 N 条情境（第 0 步先定分布：日常 70% / 边界 30%）。
- **必须覆盖的边界族（≥12 族，每族 ≥100 条）**：极饿、极困、刚睡醒、深夜、猫砂脏、
  有人在旁边但粘人=0、粘人=9、好奇心=9、懒=9、食物在嘴边、玩具在对角、
  `last` 与当前欲望冲突（例如刚睡醒又被喂）。
- **验收口径**：`uv run python -m pocket_pet.sample --n 50000 --seed 7 --out data/situations.jsonl`
  → ①同 seed 重跑输出**逐字节相同**；②`--report` 打印每字段分布与 12 族计数，**每族 ≥100**。
- **反作弊**：同 seed 幂等 + 族计数必须由脚本从产物**重新统计**得出，不能用生成时的自报值。

### REQ-0001-004 种子标注（人类（我）逐条推理）

- **范围**：≥300 条情境，由我逐条给出目标 + 紧急度（0–3）+ **一句理由**，落 `data/seed.jsonl`。
- **验收口径**：JSONL 每行 `{id, state, goal, urgency, reason}`；`reason` 非空且 ≤ 40 字；
  8 个目标**每个 ≥ 20 条**；12 个边界族**每族 ≥ 10 条**（脚本 `uv run python -m pocket_pet.check_dataset --seed-only` 校验）。
- **反作弊**：`reason` 必须与该行的 `state` 字段有实质关联（脚本抽查：`reason` 中至少出现
  一个来自 `state` 的字段名或其值，否则判 fail）。

### REQ-0001-005 API 标注器（deepseek-flash，带成本记账）

- **范围**：用 `deepseek-flash` 批量标注 REQ-003 的情境，输出与 REQ-004 同构的 JSONL。
- **必须**：非思考模式；**JSON 输出**；固定前缀（系统提示 + 我的种子示例）以命中 prompt 缓存；
  断点续跑（已标注的 id 跳过）；**逐请求记账 token 与费用**并汇总。
- **验收口径**：①`uv run python -m pocket_pet.label --limit 100` 输出 100 条且
  **schema 校验通过率 ≥ 99%**，**记账花费 ≤ ¥0.10**；②全量 5 万条跑完后
  **实测总花费 ≤ ¥40**（记账文件 `data/label_cost.json` 与 `data/labeled.jsonl` 行数一致）。
- **反作弊**：记账必须来自 API 返回的 `usage` 字段（不是本地估算）；命令里必须能复现"同一条
  重跑会被跳过"的证据（第二次运行 0 请求）。

### REQ-0001-006 数据集纪律（防泄漏）

- **范围**：训练 / 校验 / **留出评测**三集互斥；评测集**只由我手标**，永不进 API 标注管线。
- **验收口径**：①`uv run python -m pocket_pet.check_dataset --leak` 按行 hash 证明三集无交集，
  输出 `NO_LEAK train=N val=N eval=N`；②评测集 ≥ 500 条，且 `data/eval_hand.jsonl` 的
  `source` 字段全为 `hand`。
- **反作弊**：泄漏检查必须按**状态行的规范化文本**做 hash（不是按 id）。

### REQ-0001-007 学生模型训练（14M，与我的标注对齐）

- **范围**：训练 14M 学生（dim 384 / 8 层 / 8 头 / 词表 ≤ 64 / seq 64），从种子 + API 标注中学习。
- **验收口径**：①训练脚本与配置入仓并可复现（同 seed 同 loss 曲线 ±1%）；②在留出评测集上
  **目标一致率 ≥ 60%**，并在 `docs/plan/v1-index.md` 记录实测值（不是目标值）。
- **反作弊**：评测必须用 REQ-006 的留出集；报告里同时给出**混淆矩阵**，防止"全押 seek_food"刷分。

### REQ-0001-008 上板（零改动复用内核）

- **范围**：Q4 量化权重 ≤ 8 MB，放进现有固件的 flash 分区，用现有推理路径跑。
- **验收口径**：①量化后权重尺寸 ≤ 8 MB（`ls -l` 证据）；②设备上
  `audio`-equivalent 的自检 `q4_model_dot_check` 返回全一致；
  ③实测生成速度 ≥ 8 tok/s（P4，日志数字为证）。
- **反作弊**：必须跑在**真机**上（不是主机模拟），且日志里出现模型自己的状态行与目标。

### REQ-0001-009 反射层：不依赖模型也能活 `[已由 ECN-0001 变更验收口径]`

- **范围**：猫的世界（房间分区、食盆、猫砂盆、猫爬架、窗台、玩具、人的位置）+ 连续行为
  （走动、进食、睡觉、上厕所、伸爪）。
- **验收口径**（ECN-0001 修正）：①关闭 LLM（`--no-advisor`）跑无头模拟 5 分钟，
  **无 panic、无卡死**，出现 **≥4 个目标**，且所有驱动值保持在 0–9（脚本断言）；
  ②开启顾问后同一场景下**覆盖 ≥8 个目标**，且与 ① 相比至少 3 个目标的出现次数变化 ≥50%。
  （原口径要求反射层覆盖 8 个目标，与"跟随人属于策略层"自相矛盾——见 ECN-0001。）
- **反作弊**：覆盖率由模拟器**运行期统计**输出，不能写死。

### REQ-0001-010 E2E（端到端用户流程）

- **范围**：无头模拟器 + `pytest tests/e2e/`：从空状态开始，猫完成
  `seek_food → 吃 → play → 回窝 sleep` 一条完整链路。
- **验收口径**：`pytest tests/e2e/ -q` 全绿；测试内断言链路上每个阶段的状态行与目标，
  失败时打印最后 50 帧状态（可诊断）。
- **反作弊**：E2E 必须走**真实的目标选择路径**（调 `advisor.choose()`），不能直接调反射层函数绕过。

## 3. 约束（不接受什么）

- 不接受"只做改名/空壳"就宣称完成（见每条的反作弊条款）。
- 不接受把评测集混进训练（REQ-006 是硬门禁）。
- 不接受为了省事改推理引擎或网络架构（REQ-008 的"零改动"是范围约束）。
- 不接受"看起来像猫"这类软口径（VISION 的 1–3 条已全部量化）。
