# ECN-0003: 口渴（thirst）做成反射层专属驱动，不进模型状态行

## 基本信息

- **ECN 编号**：ECN-0003
- **关联 PRD**：PRD-0001
- **关联 Req ID**：REQ-0001-001（状态行字段集）、REQ-0001-009（反射层职责）
- **发现阶段**：v1.1 的交互实现（用户要求"能给猫加水"）
- **日期**：2026-10-17

## 变更原因

用户要求板子上能**给猫加水**。要让"喝水"成为猫自己会做的事，最直觉的做法是给状态行加一个
`thirst` 字段。但那会连锁作废三样东西：17 字段的 schema、以此生成的 **49,950 条 API 标注**、
以及已经上板验证过的 14.2M 模型（花掉 ¥8.35 与一夜）。

而"口渴"本身**不是选择题**：渴到一定程度必须喝水，没有"要不要"的余地。
把它交给模型（顾问层）判断，等于让一个统计模型去决定生理硬需求 —— 那正是 ECN-0001
划给反射层的地盘。

## 变更内容

### 原设计（隐含）

> 加 `thirst` 字段到状态行（17 → 18 字段），重新标注、重新训练、重新导出。

### 新设计

1. `thirst` 是**反射层专属驱动**：固件里有这个值，会漂移、会被 `water` 交互改变，
   **但不出现在送给模型的状态行里**（状态行严格保持 17 字段）。
2. 反射层规则：`thirst >= 6` → 目标强制为 `drink`（第 9 个目标，模型不知道它），
   覆盖模型给出的任何目标；喝到水后 `thirst` 掉 5，控制权交还模型。
3. `drink` 的动作与其他目标同构：走向水碗 → 低头 → 驱动值下降（画面与日志都可见）。
4. 文档层面：`docs/pet/state_line.md` 保持 17 字段不变；`cat_world.h` 里写清
   "CAT_DRIVES = 10（9 个进状态行 + thirst）" 与原因。
