# v1.1 板上验收证据（M5Stack Tab5 / ESP32-P4 rev v1.3，COM9）

> 这份文件只放**真机日志原文**与它证明了什么。文档其余部分引用它。

## 1. 屏幕：横屏铺满，PPA 不可靠 → CPU 转

```
M5Stack Tab5: Discovered board version 2 (LCD ST7123, Touch ST7123, FW 3)
display: room built 1280x720 from 640x360
display: glass up 720x1280 portrait, drawn 1280x720 landscape via PPA, cat 128 px
```

- 玻璃是 **720×1280 竖屏**，DPI 扫描布局固定：`esp_lcd_panel_swap_xy()` **不会旋转**，
  只会把扫描搞乱（实测花屏，2026-10-17 的教训）。
- PPA 旋转 **只覆盖了 1280×720 输入的下面 2/3**（SRM 块限制；鱼缸转 720×405 从未碰到），
  未覆盖的 1/3 是 PSRAM 未初始化噪声。
- 最终解：**CPU 转 90°**，并且只转**脏矩形**（猫的旧位置 + 新位置，2×128×128 ≈ 3.3 万像素/帧），
  DSI 缓冲常驻、首帧整幅铺一次。

## 2. 帧率

```
display: cat drink at (339,537) cell 0,0 painted 4400 px | 20 fps
display: cat seek_food at (292,514) cell 3,1 painted 4112 px | 18 fps
```

20 → 8（整帧 CPU 转）→ **18–20 fps**（脏矩形转）。精灵每帧实画 4100–4400 像素，
坐标每秒都在变 —— 这是"猫真的在动"的判据。

## 4. 反射层 ↔ 顾问层交权（修掉一个永久否决）

```
cat: brain[1]: drink -> seek_food (1883 ms)
cat: hunger 9 energy 0 bored 9 litter 9 thirst 0 | goal seek_food | time dawn | 18 fps
display: cat seek_food at (292,514) cell 3,1 painted 4112 px
```

- 旧 bug：`drink` 的解渴条件挂在 `water_left > 0` 上，而存档里水碗是空的
  → 口渴永远不掉 → 反射层**永久**压住模型 → 猫站在水碗前不动、饿到 9 也不去吃饭。
- 修法：站在水碗边**一定**解渴（`water` 仍负责把碗加满，但不再是前提）；
  反射层变为**限时垄断**（10 秒拿不出结果就 snooze 2.5 分钟）。
- 证据：thirst 9 → 0、goal `drink` → `seek_food`、随后它真的走向食盆。

## 5. 断电记忆与真实时钟

```
cat: cat remembered: hunger 9 energy 0 goal explore
cat: ... | goal drink | time dawn | 18 fps
```

- `nvs` 存 10 个驱动值 + 位置 + 当前目标 + 猫粮/水/猫砂状态，开机恢复。
- `time` 读 **RX8130CE @0x32** 的 BCD 小时（0x12），映射 dawn/day/dusk/night ——
  之前恒为 `day`，等于只喂给模型训练分布的 1/4。

## 6. 交互

控制台（`esp_console`，`cat>` 提示符）：`food` `water` `play` `pet` `clean` `status` `cat` `bench`
`dotcheck` `info` `bright`。

```
food: food bowl filled
touch: tap the bowl, the toy, the cat, the box     (ST7123, Max.X 720 Max.Y 1280, 10 点)
```

触摸按区域命中：食盆→喂、水碗→加水、玩具→陪玩、猫砂盆→清洁、猫爬架→抓挠、猫身上→撸。
命中日志同时打印**原始坐标**与**算出的屏幕坐标**，键位偏差可据此校准。

## 未完成 / 已知限制

1. **触摸键位未按实物校准**（逻辑已通，坐标映射一次未对照验证）。
2. 状态行 `time` 的时段边界（5/10/17/21 点）是按人作息拍的，可按猫的作息再调。
3. 猫粮碗空了之后 `seek_food` 会持续（模型的选择，不是反射层），行为上像"饿猫守着空碗" —— 可接受但可优化。
